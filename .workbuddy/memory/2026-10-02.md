## 初始化 Search-enhance UserScript 仓库

**目标**：本地 Git 仓库，用于制作增强搜索引擎用户体验的 UserScript。

**用户决策**：
- 首要引擎 **Bing**（www.bing.com / cn.bing.com 搜索结果页），Google / 百度为后续扩展位
- 工程化方式：**TypeScript + esbuild**（非 Vite、非单文件）

**架构约定（后续开发须遵守）**：
- `src/types/engine.ts` 的 `EngineAdapter` 收敛**所有**引擎差异（选择器、URL 参数名、DOM 提取）。
  引擎专属选择器不得散落到 `src/features/`。
- `src/types/feature.ts` 的 `Feature` 只描述「做什么」，通过 `engines: EngineId[] | 'all'` 声明作用范围。
- `src/meta.ts` 是 `@match` / `@grant` 的**单一真源**；版本号从 `package.json` 读取，改版本只改 package.json。
  `EngineId` 类型由 `ENGINE_IDS` 常量推导，不要硬编码字面量联合。
- Bing/Google/百度换词都是 SPA 行为，`core/dom.ts` 的 `onUrlChange()` 同时打了
  `pushState`/`replaceState` 补丁 + `popstate` 监听——只靠 popstate 会漏掉大部分换词。
- 功能开关存 GM 键 `search-enhance:features`，结构 `{ featureId: boolean }`。
- 接入新引擎三步：engines/index.ts 改 `enabled: true` → meta.ts 把 MATCHES_FUTURE 移入 MATCHES_ACTIVE → 实测校正选择器。

**已实现功能**：隐藏广告位（hide-ads）、j/k 键盘导航 + 链接新标签打开（result-navigation）。

**验证状态**：`npm run check`（tsc --noEmit）通过；构建产物 16.2 KB，UserScript 头部正确注入。

## 本机环境踩坑（重要）

1. **esbuild postinstall 报 `spawnSync node.exe EBUSY` (errno -4082)**
   托管版 node.exe 被锁，esbuild 的 install.js 校验二进制时 spawn 失败。
   解法：用系统 Node `C:/Program Files/nodejs/npm.cmd` 安装；新版 npm 会拦 postinstall
   （`npm warn install-scripts`），需手动补跑
   `"C:/Program Files/nodejs/node.exe" node_modules/esbuild/install.js`。
   已写入 README。

2. **npm install 走沙箱代理极慢**：默认 registry 5 分钟无产出。
   加 `--registry=https://registry.npmmirror.com` 后 3 秒完成。后续装依赖默认带这个参数。

3. **`declare namespace GM {}` 在 module 上下文中不产生全局作用域**，
   改用 `declare var GM_xxx` 才能让 `GM_getValue` 等被 tsc 解析到。
